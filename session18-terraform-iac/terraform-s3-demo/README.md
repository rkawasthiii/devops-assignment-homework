# Terraform S3 Demo

> **Student:** Radhey Kawasthi (Enrollment: 10242)

Creates an **AWS S3 bucket** with versioning, AES256 encryption, and all public access blocked — using Terraform (v1.16.5, AWS provider v5.100.0).

## Project layout

```text
terraform-s3-demo/
├── provider.tf        # terraform block + aws provider, region from var
├── variables.tf       # aws_region, bucket_name, environment
├── main.tf            # aws_s3_bucket + versioning + encryption + public-access-block
├── outputs.tf         # bucket_name, bucket_arn, bucket_region
├── terraform.tfvars   # concrete values
└── .terraform.lock.hcl # pinned provider versions (generated by init)
```

## The workflow — executed

### `terraform fmt` — format code to canonical style

```bash
$ terraform fmt -recursive
$ terraform fmt -check -recursive   # exits clean — all files formatted
```

### `terraform init` — download providers (real output)

```text
Terraform has created a lock file .terraform.lock.hcl to record the provider
selections it made above.

```

### `terraform validate` — syntax & internal consistency check (real output)

```text
Success! The configuration is valid.
```

### `terraform show` / `terraform output` — inspect state


> **Note:** `init`, `fmt`, and `validate` were executed for real (output above).
> `plan`/`apply`/`show`/`output`/`destroy` require AWS credentials
> (`aws configure` / env vars `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY`); the
> outputs shown are what these commands produce once credentials are configured —
> run them against a real account to create the bucket.
